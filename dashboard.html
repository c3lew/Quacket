等你決定:「更新不用重開程式」和「快捷鍵跳到挑 issue 那區」這兩個你提過的想法 — 要現在插隊做,還是等目前這條線(還有兩個功能)做完?我的建議是等做完,這條線每一格都在補「報告不會弄丟、不會變兩篇」,中間插隊會讓半成品多待幾天。
那個小毛病是什麼:送出的時候如果卡到一半沒下文,程式在硬碟上把它記成「失敗」,但實際處理的時候當成「還不確定」在走 — 行為是對的,兩個字不一致而已,只有以後查問題的人會被那個字誤導。你確認過之後再修。

最近幫你做的決定

  • 8/16重開後的自動確認,會先等幾秒再去問 GitHub — 因為剛送出去的東西,GitHub 那邊要幾秒才查得到,問太快會得到「沒有」而害你被送兩份。代價:自動確認從一瞬間變成最多等 18 秒,但這個等待完全在背景,你照樣能打字。
  • 8/16那個「查太快會送兩份」是實測抓到的,不是猜的 — 用真的 GitHub 量了兩輪,剛開好的報告要 4.3 秒和 6.9 秒才查得到。修完重測三次都只送一份。
  • 8/16有一條自動檢查是直接改硬碟上的紀錄來製造情況,不是從畫面操作出來的 — 因為那個情況從畫面根本做不出來。代價:以後存檔格式改了,這條檢查要跟著改。
  • 8/15「畫完標註再送」這條不補自動檢查,改由你換裝新版後親手驗一次(已驗過,新內容有帶到)— 比補一套測試快,也更接近你真的會怎麼用。
  • 8/15自動檢查沿用現有工具,不多裝一套真瀏覽器測試 — 一個指令幾秒跑完;代價是測的是模擬視窗,不是真的程式視窗。要換隨時換得掉。
